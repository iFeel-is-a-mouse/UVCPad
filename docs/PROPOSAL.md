## 1. 背景

工作区已有两个成熟项目，本次是整合二者并新增透明触控层：

**① hdmi2mp（已交付 v1）— 显示能力**

- Android App，Kotlin，基于 AUSBC 3.6.0 库。
- MS2130 HDMI→USB 采集卡（UVC 协议）接入平板，全屏实时显示 HDMI 输入。
- 效果：把平板变成 HDMI 监视器，插上即出画面。
- 技术要点：OPENGL 渲染 + `AspectRatioTextureView`，1920×1080 / 1872×1404 两组预设，支持截图。

**② KeysJoy（F-Droid 发布 v1.0.1）— 触控能力**

> 用户原始需求中的 "keyjoys" 即指本项目 KeysJoy，目录为 `projects/KeysJoy/`，包名 `com.github.ifeel.keysjoy`，git remote `git@github.com:iFeel-is-a-mouse/KeysJoy.git`。基于 Kontroller 深度改造，用 `BluetoothHidDevice` API 把安卓设备注册为蓝牙 HID 设备（键盘+鼠标），对端无需驱动。

- **横屏三栏布局**：左侧键盘 + 中央触控板 + 右侧键盘，分隔条可拖动调节宽度。
- **竖屏全屏触控板**：整屏作为触控板，单指移光标、手势控制。
- **手势引擎**：tap / 长按拖拽 / 双击拖拽 / 双指滚动。
- **独立鼠标三键**：左键 / 滚轮 / 右键。
- **5 档速度预设**；多设备配对自动重连；导航键（向主机发送 Meta 快捷键）。

> 注：KeysJoy 是"键盘 + 鼠标"双能力项目，但 **uvcpad 仅取其触控板/鼠标能力，不含键盘**（见 8.1 节 Q2 决策）。

## 3. 目标

**一句话目标：**

> PC 屏幕内容经采集卡显示在 pad 上；pad 同时作为**透明触控板**，通过蓝牙 HID 把触控操作传给 PC，实现"横屏 pad = PC 的透明触控显示器"。

拆开看，是三个能力的叠加：

1. **看**：pad 显示 PC 画面（复用 hdmi2mp 显示链路）。
2. **触**：pad 触摸手势转换为蓝牙 HID 鼠标事件，控制 PC 光标（复用 KeysJoy 触控板链路；横屏形态为单一全屏触控板，Q2 已确认）。
3. **透**：触控层是透明的，透出底层采集画面，两者叠加使用。

**关键体验闭环：** 用户在 pad 上看到 PC 画面（含 PC 渲染的光标），手指在透明层上滑动 → PC 光标移动。看和触在同一块屏上，所见即所控。

**交互入口：** 全屏触控板上不放可点击按钮（点击即单击手势，见需求理解第 6 点），唯一常驻 UI 是横屏顶部的一个下拉三角——点击三角唤出**自动隐藏的按键栏**（合并 KeysJoy 菜单与 hdmi2mp 菜单：速度预设、设备/蓝牙连接、分辨率、截图等，**不含键盘设置项**），数秒无操作后自动消失。

## 4. 需求理解

我对需求的理解，陈述如下：

1. **这不是两个独立 App 的简单并存，而是一个叠加态。** 采集画面是底层，触控板是浮在其上的透明层。用户看到的是"画面 + 透明触控板"的合体，不是切换使用。

2. **透明触控板 = 手势识别层，不是虚拟光标层。** 光标由 PC 渲染并显示在采集画面里，pad 透明层不画光标、不画常驻按钮（唯一例外：顶部下拉三角入口，见第 6 点），只负责把手指手势翻译成 HID 鼠标报告。这正是"透出采集内容"的含义。

3. **手势映射沿用 KeysJoy 触控板约定**：单指滑动 → 相对位移（dx/dy）、tap → 左键、长按/双击 → 拖拽、双指滚动 → 滚动。相对位移是核心——PC 光标已经显示在画面里，pad 端不需要绝对坐标对齐。

4. **横向是唯一形态**（用户已确认横屏；需求原文的"蓝牙竖屏板"按横向理解），不做竖屏/横竖切换。

5. **复用优先**：两项目已验证的采集管线、HID 报告协议、手势逻辑直接搬，新开发集中在"透明层整合"这一件事上。

6. **全屏触控板与"点击式按钮"天然冲突。** 触控板上任何可点击区域都会被识别为单击手势（tap → 左键），因此功能按钮不能直接摆在触控板上。所有功能入口必须改为**非点击式触发**——本次方案用"顶部下拉三角"规避此冲突。

7. **下拉三角是唯一常驻 UI。** 横屏顶部边缘一个小三角，点击后顶部滑出按键栏。三角区域的事件被自身消费、不穿透到触控板（不会误触发单击手势）；按键栏数秒无操作自动隐藏，把屏幕还给触控板。

8. **按键栏 = KeysJoy 菜单 + hdmi2mp 菜单合并。** 一个入口承载两个来源的功能：KeysJoy 侧的速度预设、设备/蓝牙连接、多设备切换；hdmi2mp 侧的分辨率预设、截图等。**按键栏不含键盘相关设置项——uvcpad 是纯触控板，没有键盘功能。**

## 5. 两条链路

```
┌───────────────────── pad（Android） ─────────────────────┐
│                                                          │
│  ┌─ 显示链路（复用 hdmi2mp）────────────────────────┐   │
│  │ PC HDMI → MS2130 采集卡 → pad USB → UVC 采集      │   │
│  │ → OPENGL 渲染 → 全屏显示（底层画面）              │   │
│  └────────────────────────────────────────────────────┘   │
│                          ▲ 叠加                           │
│  ┌─ 触控链路（复用 KeysJoy）───────────────────────┐   │
│  │ pad 触摸手势 → 手势识别（透明层）                 │   │
│  │ → ScrollableTrackpadMouseReport (ID=4, 7B)        │   │
│  │ → BluetoothHID → PC 光标移动/点击/滚动/拖拽        │   │
│  └────────────────────────────────────────────────────┘   │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

| 链路 | 方向 | 复用来源 | 职责 |
|---|---|---|---|
| 显示链路 | PC → pad | hdmi2mp | 采集卡画面进 pad 屏幕 |
| 触控链路 | pad → PC | KeysJoy | 触摸手势控制 PC 光标 |

两条链路互相独立、并行工作，在视觉上通过"透明层"合成。

## 6. 架构设想

> 此节为方向性设想，供确认需求时参考，非最终设计。

### 6.1 整合形态：建议单 App 整合

| 方案 | 说明 | 评价 |
|---|---|---|
| **A. 单 App 整合（建议）** | 一个 App 内同时承载采集显示与透明触控层 | 状态共享简单（触控层直接拿到采集会话状态），启动顺序可控，体验顺滑 |
| B. 双 App 协作 | hdmi2mp 负责显示，KeysJoy 改造为 overlay 触控 | 解耦干净，但两个前台服务叠加、屏幕常亮、蓝牙连接状态互相通信，复杂度反而更高 |

**倾向方案 A。** 双 App 的"解耦"收益在单设备场景下不成立，反而引入跨进程同步成本。

### 6.2 分层设想（单 App）

```
┌──────────────────────────────────────┐
│  UI 层：顶部下拉三角（常驻入口，       │
│  事件不穿透到触控板）                 │
│  └ 按键栏（自动隐藏，合并两菜单）      │
├──────────────────────────────────────┤
│  触控层（全屏透明模拟触控板，         │
│  接收触摸事件）                      │
│  ├─ 手势识别（复用 KeysJoy 逻辑）      │
│  ├─ 坐标→相对位移映射（调参点）        │
│  └─ HID 报告发送（复用报告协议）       │
├──────────────────────────────────────┤
│  显示层（AspectRatioTextureView）     │
│  └─ UVC 采集 + OPENGL 渲染（复用）    │
├──────────────────────────────────────┤
│  基础：蓝牙连接管理（复用 KeysJoy）     │
└──────────────────────────────────────┘
```

### 6.3 核心设计点（需求层面）

1. **透明层不挡画面。** 触控层只接收事件、不绘制内容（或仅绘制极淡的提示边框）。
2. **坐标映射。** 手指位移按灵敏度系数转换为 dx/dy，复用 KeysJoy 的 5 档速度预设。
3. **触控与渲染分离。** 触摸事件处理与 UVC 渲染线程解耦，避免互相阻塞。
4. **蓝牙与采集并行。** 采集卡占 USB，蓝牙走无线，天然并行，无资源冲突。
5. **三角区域事件拦截。** 下拉三角是触控板上的"豁免区"：落在三角区域的事件由三角消费，不进入触控板手势层——点三角不会误触成"单击左键"。
6. **按键栏自动隐藏。** 按键栏展开后，N 秒无操作自动消失（默认 3–5s，待确认，见 Q7），不长期遮挡触控板。
7. **按键栏优先消费事件。** 按键栏展开期间，其区域内的触摸事件由菜单消费、不进入触控手势层，避免点菜单被当成触控手势。

## 7. 复用清单

### 7.1 从 hdmi2mp 复用

- MS2130 / UVC 采集与设备接入逻辑（AUSBC 3.6.0）
- OPENGL + `AspectRatioTextureView` 渲染管线
- 分辨率预设（1920×1080 / 1872×1404）与自动回退逻辑
- 截图功能（是否保留，见待确认问题）

### 7.2 从 KeysJoy 复用（仅鼠标/触控板能力）

只复用 KeysJoy 的鼠标/触控板相关能力：

- `BluetoothHidDevice` 注册与蓝牙权限体系（Android 12+，**仅注册鼠标报告，不注册键盘报告**）
- 全屏触控板手势识别（tap / 长按拖拽 / 双击拖拽 / 双指滚动）
- `ScrollableTrackpadMouseReport`（ID=4，7B）协议与发送器（KeysJoy 源码 `reports/ScrollableTrackpadMouseReport.kt` 中确认存在）
- 自动重连、多设备切换
- 5 档速度预设

> **键盘相关能力不在复用范围**：键盘 HID 报告、横屏三栏布局（左右键盘栏）、导航键等均不复用——**uvcpad 是纯触控板，不含键盘**。

### 7.3 新开发（本次核心）

- **透明触控层**：叠加在采集画面上的全屏透明触摸层
- **整合外壳**：单 App 工程骨架，两条链路装配
- **协调逻辑**：采集会话、蓝牙连接、触控层的生命周期管理

## 10. 风险与假设

1. **触控灵敏度调参**：蓝牙 HID 相对位移在 PC 上的手感（加速度、灵敏度）需要实测调参，KeysJoy 的速度预设可复用。
2. **帧率与触控刷新率**：UVC 60fps 采集与触摸事件采样是两个节奏，需保证触摸响应不被渲染卡顿拖累（线程分离）。
3. **蓝牙延迟**：HID 报告走蓝牙，延迟受环境干扰，需在真实设备上验证 ≤ 100ms 的可行性。
4. **假设**：pad 只有一个 USB-C 口且被采集卡占用，蓝牙必须走无线——此假设下两条链路无资源冲突。
